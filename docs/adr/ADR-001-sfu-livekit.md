# ADR-001: 실시간 영상 스트리밍에 SFU(LiveKit) 선택

## 상태

**Accepted** (2025-06)

## 맥락

화재 감지 시 엣지 디바이스(Raspberry Pi)에서 촬영한 CCTV 영상을 다수의 모바일 앱 사용자에게 실시간으로 전송해야 한다. WebRTC 기반 스트리밍 아키텍처는 크게 세 가지 방식이 있다:

| 방식                                | 설명                                                                        |
| ----------------------------------- | --------------------------------------------------------------------------- |
| **P2P (Mesh)**                      | 피어 간 직접 연결. 참여자 N명일 때 엣지 디바이스가 N개 업링크를 유지해야 함 |
| **MCU (Multipoint Control Unit)**   | 서버가 모든 미디어를 디코딩·합성·재인코딩 후 클라이언트에 전송              |
| **SFU (Selective Forwarding Unit)** | 서버가 미디어를 디코딩 없이 선택적으로 포워딩. 엣지는 1개 업링크만 유지     |

### 핵심 제약 조건

1. **엣지 디바이스 리소스 제한**: Raspberry Pi 5는 CPU 4코어, RAM 8GB. YOLO 추론이 이미 CPU를 상당히 사용 중
2. **1:N 스트리밍**: 하나의 카메라 영상을 해당 방(Room)의 모든 멤버에게 동시 전송
3. **녹화(Egress) 필요**: 화재 이벤트 발생 시 영상을 S3에 녹화 보관

## 결정

**SFU 방식의 LiveKit을 선택**한다.

### 선택 근거

1. **엣지 리소스 절약**: 엣지 디바이스는 SFU 서버로 1개의 업링크만 유지하면 되므로 CPU/네트워크 부담 최소화
2. **1:N 확장성**: SFU가 N명의 시청자에게 영상을 포워딩하므로 시청자 수 증가에 엣지가 영향받지 않음
3. **Egress 내장**: LiveKit은 서버사이드 녹화(Egress) 기능을 내장하여 별도 녹화 인프라 불필요
4. **낮은 지연**: 디코딩/재인코딩 없이 패킷을 포워딩하므로 MCU 대비 지연이 낮음
5. **오픈소스**: LiveKit은 Apache 2.0 라이선스로 자체 서버 운영 가능

## 대안 분석

### P2P (Mesh) — 기각

- 장점: 서버 불필요, 인프라 비용 0
- 단점: Raspberry Pi가 시청자 수만큼 업링크를 유지해야 하므로 3명 이상 시청 시 CPU/대역폭 한계. YOLO 추론과 동시 실행 불가능

### MCU (Jitsi, Kurento) — 기각

- 장점: 클라이언트 부담 최소 (합성된 단일 스트림 수신)
- 단점: 서버에서 디코딩+재인코딩하므로 CPU 비용이 매우 높음. m5.xlarge 인스턴스로도 동시 5~10개 Room이 한계. 녹화 시 추가 트랜스코딩 필요

### LiveKit 외 SFU (mediasoup, Janus) — 기각

- mediasoup: Node.js 기반으로 성능 우수하나, Egress/Ingress 기능 없어 녹화를 별도 구현해야 함
- Janus: C 기반으로 고성능이나 학습 곡선이 높고, SDK 생태계가 LiveKit 대비 부족

## 결과

### 긍정적

- 엣지 디바이스의 CPU 사용률이 YOLO 추론 포함 약 60%로 안정적 운영
- LiveKit Egress로 화재 이벤트 녹화 자동화 구현 완료
- Python/Java/React Native SDK가 모두 제공되어 전체 스택 통합 용이

### 부정적

- LiveKit SFU 서버 운영에 m5.xlarge 인스턴스 필요 (WebRTC의 CPU 집약적 특성)
- 월 약 $140의 추가 인프라 비용 발생 (AWS 운영 시)
- 로컬 개발 환경에서 NAT/TURN 설정이 필요할 수 있음

### 트레이드오프 요약

```
엣지 리소스 절약 + 1:N 확장성 + 내장 녹화  ←→  서버 인프라 비용 증가
```
