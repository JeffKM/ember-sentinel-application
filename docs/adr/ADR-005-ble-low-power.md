# ADR-005: 엣지-아두이노 간 BLE 저전력 경보 설계

## 상태

**Accepted** (2025-05)

## 맥락

화재 감지 시 현장에서 즉각적인 경보음을 울려야 한다. Raspberry Pi(엣지 디바이스)와 Arduino Nano 33 BLE(경보 장치) 간 통신 방식을 결정해야 한다.

### 제약 조건

1. **배터리 운영**: Arduino Nano 33 BLE는 배터리로 동작하며 장기간(1년+) 교체 없이 운영 목표
2. **즉각 응답**: 화재 감지 후 경보음까지 지연 최소화 (1초 이내)
3. **통신 거리**: 실내 환경 기준 10~15m 범위
4. **단방향 명령**: Raspberry Pi → Arduino로 "경보 ON" 명령만 전송

### 후보 통신 방식

| 방식                           | 전력 소모 | 지연   | 범위        | 복잡도    |
| ------------------------------ | --------- | ------ | ----------- | --------- |
| **BLE (Bluetooth Low Energy)** | 매우 낮음 | ~100ms | 15m         | 낮음      |
| **Wi-Fi**                      | 높음      | ~50ms  | 30m         | 중간      |
| **유선 (GPIO/UART)**           | 없음      | <1ms   | 물리적 제약 | 매우 낮음 |
| **Zigbee**                     | 낮음      | ~200ms | 100m+       | 높음      |

## 결정

**BLE(Bluetooth Low Energy)를 사용하고, 1.6% 듀티 사이클로 저전력 운영**한다.

### 설계 상세

| 항목      | 값                                                | 근거                            |
| --------- | ------------------------------------------------- | ------------------------------- |
| BLE 역할  | Arduino = Peripheral (GATT Server), RPi = Central | RPi가 능동적으로 연결·명령 전송 |
| 연결 방식 | 필요 시 연결 (on-demand connect)                  | 상시 연결 대비 전력 90% 절감    |
| 스캔 주기 | 500ms 스캔 / 30초 간격                            | 1.6% 듀티 사이클                |
| 경보 동작 | 부저 10초간 ON/OFF (0.5초 간격)                   | 주의 환기에 충분한 길이         |
| 쿨다운    | 10초                                              | 연속 감지 시 중복 경보 방지     |

### 전력 소모 추정

```
스캔 시 전류: ~15mA (500ms)
대기 시 전류: ~0.005mA (29.5초)
평균 전류: 15mA × (0.5/30) + 0.005mA × (29.5/30) ≈ 0.255mA
CR2032 배터리 (225mAh): 225 / 0.255 ≈ 882시간 ≈ 36.8일

※ 실제로는 Arduino의 Deep Sleep 모드 적용 시 대기 전류가 더 낮아져 수개월 운영 가능
```

## 대안 분석

### Wi-Fi — 기각

- 장점: 긴 범위, 빠른 응답
- 단점:
  - Arduino Nano 33 BLE에 Wi-Fi 모듈 없음 (별도 보드 필요)
  - Wi-Fi 유지만으로 ~80mA 소모 → 배터리 수시간 내 방전
  - 경보 장치에 Wi-Fi 인프라 의존은 화재 시 네트워크 장애와 맞물릴 위험

### 유선 연결 (GPIO) — 기각

- 장점: 지연 없음, 전력 소모 없음
- 단점:
  - 물리적 배선 필요 → 설치 위치 제약
  - Raspberry Pi와 Arduino 간 거리 제한 (수 cm ~ 수 m)
  - 화재 감지 카메라와 경보 부저의 최적 설치 위치가 다를 수 있음

### Zigbee — 기각

- 장점: 메시 네트워크, 긴 범위, 저전력
- 단점:
  - Arduino Nano 33 BLE에 Zigbee 모듈 미내장 → 추가 하드웨어 필요
  - 1:1 통신에 메시 네트워크는 과잉
  - 개발 복잡도 증가 (Zigbee 스택 구현)

## 결과

### 긍정적

- Arduino Nano 33 BLE의 내장 BLE 모듈만으로 추가 하드웨어 없이 구현
- Python `Bleak` 라이브러리로 RPi 측 BLE Central 구현 용이
- 화재 감지 후 경보까지 약 200ms 이내 달성
- 무선 통신으로 경보 장치 설치 위치 유연

### 부정적

- BLE 연결 간헐적 실패 가능 → 재시도 로직 필수 (지수 백오프 적용)
- 실내 장애물(벽, 금속 구조물)에 의한 신호 감쇠
- `--no-ble` 모킹 옵션 없이는 개발/테스트 시 실물 Arduino 필요

### 트레이드오프 요약

```
배터리 장기 운영 + 무선 유연성 + 내장 BLE 활용  ←→  연결 불안정 가능성 + 범위 제한
```
